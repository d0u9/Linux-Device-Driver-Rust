# How is rust module loaded into Kernel

We have talked the Loading process of Linux module file. For rust, the process
is same because modules compiled from either Rust or C are all ELF dynamic
linked files. They should have same ABI (Application Binary Interface) which
is compatible with Kernel's dynamic linker.

The `module!{ }` macro we have talked in previous section is responsible for
bootstrapping Rust kernel modules. It reads fields defined in it and expands
them to definitions of variables, functions and structures.

For a simple rust module:

```rust
#![allow(missing_docs)]

use kernel::prelude::*;

module! {
    type: ExampleModule,
    name: "example_module",
    authors: ["Douglas Su"],
    description: "An example module",
    license: "GPL",
    params: {
        uint_param: u32 {
            default: 1,
            description: "uint parameter",
        },
    },
}

struct ExampleModule {
    version: u32,
}

impl kernel::Module for ExampleModule {
    fn init(_module: &'static ThisModule) -> Result<Self> {
        let module = ExampleModule {
            version: *module_parameters::uint_param.value(),
        };

        pr_info!("Hello World! uint_param={}\n", module.version);
        pr_info!(
            "The address of module parameter uint_param: {:p}\n",
            module_parameters::uint_param.value()
        );
        Ok(module)
    }
}

impl Drop for ExampleModule {
    fn drop(&mut self) {
        pr_info!("Bye World\n");
    }
}
```

The `module!{ }` part of these piece of code will be expanded to code below
during compiling time by Rust's macro processor (generated by the `.rsi` target,
e.g. `make -C "$LDD_ROOT/src/linux-stable" M=$PWD main.rsi`):

```rust
#[doc = r" The module name."]
#[doc = r""]
#[doc = r" Used by the printing macros, e.g. [`info!`]."]
const __LOG_PREFIX: &[u8] = c"example_module".to_bytes_with_nul();
static THIS_MODULE: ::kernel::ThisModule = unsafe {
    extern "C" {
        static __this_module: ::kernel::types::Opaque<::kernel::bindings::module>;
    };
    ::kernel::ThisModule::from_ptr(__this_module.get())
};
#[doc = r" The `LocalModule` type is the type of the module created by `module!`,"]
#[doc = r" `module_pci_driver!`, `module_platform_driver!`, etc."]
type LocalModule = ExampleModule;
impl ::kernel::ModuleMetadata for ExampleModule {
    const NAME: &'static ::kernel::str::CStr = c"example_module";
}
#[doc(hidden)]
mod __module_init {
    mod __module_init {
        use pin_init::PinInit;
        #[doc = r#" The "Rust loadable module" mark."#]
        #[used(compiler)]
        static __IS_RUST_MODULE: () = ();
        static mut __MOD: ::core::mem::MaybeUninit<super::super::LocalModule> =
            ::core::mem::MaybeUninit::uninit();
        #[doc = r" # Safety"]
        #[doc = r""]
        #[doc = r" This function must not be called after module initialization, because it may be"]
        #[doc = r" freed after that completes."]
        #[no_mangle]
        #[link_section = ".init.text"]
        pub unsafe extern "C" fn init_module() -> ::kernel::ffi::c_int {
            unsafe { __init() }
        }
        #[used(compiler)]
        #[link_section = ".init.data"]
        static __UNIQUE_ID___addressable_init_module: unsafe extern "C" fn() -> i32 = init_module;
        #[no_mangle]
        #[link_section = ".exit.text"]
        pub extern "C" fn cleanup_module() {
            unsafe { __exit() }
        }
        #[used(compiler)]
        #[link_section = ".exit.data"]
        static __UNIQUE_ID___addressable_cleanup_module: extern "C" fn() = cleanup_module;
        #[doc = r" # Safety"]
        #[doc = r""]
        #[doc = r" This function must only be called once."]
        unsafe fn __init() -> ::kernel::ffi::c_int {
            let initer = <super::super::LocalModule as ::kernel::InPlaceModule>::init(
                &super::super::THIS_MODULE,
            );
            match unsafe { initer.__pinned_init(__MOD.as_mut_ptr()) } {
                Ok(m) => 0,
                Err(e) => e.to_errno(),
            }
        }
        #[doc = r" # Safety"]
        #[doc = r""]
        #[doc = r" This function must"]
        #[doc = r" - only be called once,"]
        #[doc = r" - be called after `__init` has been called and returned `0`."]
        unsafe fn __exit() {
            unsafe {
                __MOD.assume_init_drop();
            }
        }
        #[link_section = ".modinfo"]
        #[used(compiler)]
        pub static __EXAMPLE_MODULE_1: [u8; 18usize] = *b"author=Douglas Su\0";
        #[link_section = ".modinfo"]
        #[used(compiler)]
        pub static __EXAMPLE_MODULE_3: [u8; 30usize] = *b"description=An example module\0";
        #[link_section = ".modinfo"]
        #[used(compiler)]
        pub static __EXAMPLE_MODULE_5: [u8; 12usize] = *b"license=GPL\0";
    }
}
mod module_parameters {
    #[link_section = ".modinfo"]
    #[used(compiler)]
    pub static __EXAMPLE_MODULE_8: [u8; 24usize] = *b"parmtype=uint_param:u32\0";
    #[link_section = ".modinfo"]
    #[used(compiler)]
    pub static __EXAMPLE_MODULE_10: [u8; 31usize] = *b"parm=uint_param:uint parameter\0";
    #[allow(non_upper_case_globals)]
    pub(crate) static uint_param: ::kernel::module_param::ModuleParamAccess<u32> =
        ::kernel::module_param::ModuleParamAccess::new(1);
    const _: () = {
        #[allow(non_upper_case_globals)]
        #[link_section = "__param"]
        #[used(compiler)]
        static __example_module_uint_param_struct: ::kernel::module_param::KernelParam =
            ::kernel::module_param::KernelParam::new(::kernel::bindings::kernel_param {
                name: kernel::str::as_char_ptr_in_const_context(if true {
                    c"uint_param"
                } else {
                    c"example_module.uint_param"
                }),
                mod_: unsafe { core::ptr::from_ref(&::kernel::bindings::__this_module).cast_mut() },
                ops: core::ptr::from_ref(&::kernel::module_param::PARAM_OPS_U32),
                perm: 0,
                level: -1,
                flags: 0,
                __bindgen_anon_1: ::kernel::bindings::kernel_param__bindgen_ty_1 {
                    arg: uint_param.as_void_ptr(),
                },
            });
    };
}
```

## How Rust module source is compiled into object

It is intuitive that object is compiled from C source file, and Kbuild takes
this as a built-in rule. However, for Rust code, Kbuild has to be told how to
handle it and that rust source can be compiled into object.

To make Kbuild understand Rust, below lines are added in `scripts/Makefile.build`:

```makefile
quiet_cmd_rustc_o_rs = $(RUSTC_OR_CLIPPY_QUIET) $(quiet_modtag) $@
      cmd_rustc_o_rs = $(rust_common_cmd) --emit=$(if $(CONFIG_RUST_INLINE_HELPERS),llvm-bc=$(patsubst %.o,%.bc,$@),obj=$@) $< \
	$(if $(CONFIG_RUST_INLINE_HELPERS),;$(LLVM_LINK) --internalize --suppress-warnings $(patsubst %.o,%.bc,$@) \
		$(objtree)/rust/helpers/helpers$(if $(part-of-module),_module).bc -o $(patsubst %.o,%.m.bc,$@); \
		$(CC) $(CLANG_FLAGS) $(filter-out $(CC_FLAGS_LTO),$(KBUILD_CFLAGS)) \
		$(CC_FLAGS_RUST_INLINE_HELPERS) -Wno-override-module -c $(patsubst %.o,%.m.bc,$@) -o $@ \
		$(cmd_ld_single)) \
	$(cmd_objtool)

define rule_rustc_o_rs
	$(call cmd_and_fixdep,rustc_o_rs)
	$(call cmd,gen_objtooldep)
endef

$(obj)/%.o: $(obj)/%.rs FORCE
```

`rust_common_cmd` is defined in the same file. It runs `rustc` with
`--extern pin_init --extern kernel --extern zerocopy --extern zerocopy_derive`
and `-L $(objtree)/rust/`, so that our module links to the `kernel` crate.

## `init_module` and `cleanup_module` symbols

From the discussions in previous chapter, two important symbols `init_module`
and `cleanup_module` must be defined, and they will be referenced by
`struct module` which later be used to do initialization and cleanup works of
our module.

Other than the symbol name, the ABI also plays an important role. Functions
export `init_module` and `cleanup_module` symbols must obey the ABI of standard
C. For Rust code, this is implemented by decorating functions with `extern "C"`.

Functions marked as `extern "C"` will be compiled by using standard C ABI and
in turn be invoked directly by C code. Usually, `#[no_mangle]` annotation is
needed to tell the Rust compiler not to mangle the name of this function.
Mangling is when a compiler changes the name we've given a function to a
different name that contains more information for other parts of the compilation
process to consume but is less human readable.

For example, we a function in Rust:

```rust
#[no_mangle]
fn my_add(a: i32, b: i32) -> i32 { a + b }
```

If it is decorated with `#[no_mangle]` annotation, function symbol generated
will be something like:

```
0000000100001680 T _my_add
```

However, by default, Rust will mangle symbols it generated, and produce
something like this:

```
0000000100001680 t __ZN2z16my_add17hb64f7e7eb99a7564E
```

Back to our Rust code. After macro expansion, two functions are generated, and
be annotated with `#[no_mangle]`.

```rust
#[no_mangle]
#[link_section = ".init.text"]
pub unsafe extern "C" fn init_module() -> ::kernel::ffi::c_int {
    unsafe { __init() }
}
#[used(compiler)]
#[link_section = ".init.data"]
static __UNIQUE_ID___addressable_init_module: unsafe extern "C" fn() -> i32 = init_module;
#[no_mangle]
#[link_section = ".exit.text"]
pub extern "C" fn cleanup_module() {
    unsafe { __exit() }
}
#[used(compiler)]
#[link_section = ".exit.data"]
static __UNIQUE_ID___addressable_cleanup_module: extern "C" fn() = cleanup_module;
```

After compiling this Rust into object, `init_module` and `cleanup_module`
symbols are defined as strong symbols which will be used in `modpost`. When the
module file is loaded, kernel's module loader will find these two functions and
use them to init/cleanup module.

Like `__init` and `__exit` in C, the two functions are placed in `.init.text`
and `.exit.text` sections. The `__UNIQUE_ID___addressable_*` statics take their
addresses, the same as `___ADDRESSABLE()` in C's `module_init()` and
`module_exit()`.

Two functions, `__init()` and `__exit()`, are invoked in `init_module()`
and `cleanup_module()` respectively:

```rust
static mut __MOD: ::core::mem::MaybeUninit<super::super::LocalModule> =
    ::core::mem::MaybeUninit::uninit();

unsafe fn __init() -> ::kernel::ffi::c_int {
    let initer = <super::super::LocalModule as ::kernel::InPlaceModule>::init(
        &super::super::THIS_MODULE,
    );
    match unsafe { initer.__pinned_init(__MOD.as_mut_ptr()) } {
        Ok(m) => 0,
        Err(e) => e.to_errno(),
    }
}

unsafe fn __exit() {
    unsafe {
        __MOD.assume_init_drop();
    }
}
```

`__init()` function in turn calls our module structure's member function
`ExampleModule::init()`, through the `InPlaceModule` trait which is implemented
for every `kernel::Module`. The returned `struct ExampleModule` is initialized
in place in `__MOD`.

The `__exit()` function drops `__MOD`. That is because the `Drop` trait has
been implemented for our `struct ExampleModule`, and the `drop()` function will
be invoked when the instance of `struct ExampleModule` is dropped.

## Build `modinfo` section

We have talked that in module's ELF file, a special section, `.modinfo`, is used
to store information about this module. It includes the name, parameter type,
parameter name, license, author, etc.

For rust module, we have to obey this rule. The expanded rust code is self
explained:

```rust
#[link_section = ".modinfo"]
#[used(compiler)]
pub static __EXAMPLE_MODULE_1: [u8; 18usize] = *b"author=Douglas Su\0";
#[link_section = ".modinfo"]
#[used(compiler)]
pub static __EXAMPLE_MODULE_3: [u8; 30usize] = *b"description=An example module\0";
#[link_section = ".modinfo"]
#[used(compiler)]
pub static __EXAMPLE_MODULE_5: [u8; 12usize] = *b"license=GPL\0";
#[link_section = ".modinfo"]
#[used(compiler)]
pub static __EXAMPLE_MODULE_8: [u8; 24usize] = *b"parmtype=uint_param:u32\0";
#[link_section = ".modinfo"]
#[used(compiler)]
pub static __EXAMPLE_MODULE_10: [u8; 31usize] = *b"parm=uint_param:uint parameter\0";
```

A special directive `#[link_section()]` tells Rust compiler which section the
data or code it annotated will be placed in. For our example, the section
is `.modinfo`.

## Kernel module parameter

Module parameter is defined in `module!{ }` macro:

```rust
module! {
    ...
    params: {
        uint_param: u32 {
            default: 1,
            description: "uint parameter",
        },
    },
}
```

After macro expansion, in `mod module_parameters`:

```rust
#[allow(non_upper_case_globals)]
pub(crate) static uint_param: ::kernel::module_param::ModuleParamAccess<u32> =
    ::kernel::module_param::ModuleParamAccess::new(1);
```

The parameter is a static variable of type `ModuleParamAccess<u32>`, which has
the same name as our parameter, i.e. `uint_param`. It holds the default value,
and the value passed in when loading the module, which can be set only once.
Module programmer can use this variable as:

```rust
pr_info!("uint_param = {}\n", module_parameters::uint_param.value());
```

`value()` returns the passed in value, or the default value if none is passed.

## Build `__param` section

Previous chapter introduces `__param` section in ELF file and how module loader
process this section during loading time.

For Rust code, we have to build this section consistent with its C counterpart.
The `module!{ }` macro takes care of this, and you can find codes generated
from this macro like this:

```rust
const _: () = {
    #[allow(non_upper_case_globals)]
    #[link_section = "__param"]
    #[used(compiler)]
    static __example_module_uint_param_struct: ::kernel::module_param::KernelParam =
        ::kernel::module_param::KernelParam::new(::kernel::bindings::kernel_param {
            name: kernel::str::as_char_ptr_in_const_context(if true {
                c"uint_param"
            } else {
                c"example_module.uint_param"
            }),
            mod_: unsafe { core::ptr::from_ref(&::kernel::bindings::__this_module).cast_mut() },
            ops: core::ptr::from_ref(&::kernel::module_param::PARAM_OPS_U32),
            perm: 0,
            level: -1,
            flags: 0,
            __bindgen_anon_1: ::kernel::bindings::kernel_param__bindgen_ty_1 {
                arg: uint_param.as_void_ptr(),
            },
        });
};
```

`kernel::module_param::KernelParam` is a wrapper of
`kernel::bindings::kernel_param`. `kernel_param` in kernel describes single
parameter in module. We have detailed this in previous chapter, and for
convenience I paste it here again:

```c
struct kernel_param {
    const char *name;
    struct module *mod;
    const struct kernel_param_ops *ops;
    const u16 perm;
    s8 level;
    u8 flags;
    union {
            void *arg;
            const struct kparam_string *str;
            const struct kparam_array *arr;
    };
};
```

The Rust part is a mimic of C structure which initialized each field with
Rust code, either in FFI or rust variable. The structure then is compiled into
`__param` section due to the `#[link_section = "__param"]` annotation.

The `name` field is `uint_param` when built as a module, and
`example_module.uint_param` when built into the kernel image, the same as the
prefix C adds with `MODULE_PARAM_PREFIX`. `perm` is always 0, so the parameter
is not shown in sysfs.

However, the `ops` field is a little bit special. It is assigned
`&kernel::module_param::PARAM_OPS_U32`.

This variable is defined via a macro `make_param_ops!()`, and expanded during
kernel compiling time. For `PARAM_OPS_U32`, it is defined as:

```rust
make_param_ops!(PARAM_OPS_U32, u32);
```

which expands to a `kernel_param_ops` with only `set` function, `set_param::<u32>`,
which parses the passed in string and sets the value of `ModuleParamAccess`.
`get` is `None`, as the parameter cannot be read from sysfs.

## Evolution

- The module instance used to be kept in `static mut __MOD: Option<T>`.
  `__init()` stored the result of `KernelModule::init()` in it, and `__exit()`
  set it to `None`, which dropped the module. Now it is kept in
  `MaybeUninit<T>`, initialized in place through `InPlaceModule`, and dropped by
  `assume_init_drop()`.
- `init_module` and `cleanup_module` used to be placed in the default text
  section. They are in `.init.text` and `.exit.text` now, with addressable
  statics like C's `___ADDRESSABLE()`.
- A parameter used to be a `static mut` value, wrapped by a generated
  structure with the same name as the parameter, whose `read()` method took the
  parameter lock (`THIS_MODULE.kernel_param_lock()`). Now it is a
  `ModuleParamAccess<T>` static, read with `value()` without a lock.
- The `__param` entry used to be wrapped in a generated
  `*_RacyKernelParam` structure, and its `perm` came from the `permissions`
  field. It is wrapped in `kernel::module_param::KernelParam` now, and `perm` is
  always 0.
- `.modinfo` statics used to be named after the module and the field, e.g.
  `__example_module_author`. They are numbered now, e.g.
  `__EXAMPLE_MODULE_1`.
- `cmd_rustc_o_rs` used to pass `--extern alloc --extern kernel` itself. It
  reuses `rust_common_cmd` now.
- C types used to come from `kernel::c_types`. They come from `kernel::ffi`
  now.
