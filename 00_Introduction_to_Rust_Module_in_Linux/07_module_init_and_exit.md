# Module Init and Exit

## An example of C module

For C module, it has a skeleton like:

```C
#include <linux/types.h>
#include <linux/module.h>

static u32 uint_param = 1;
module_param(uint_param, uint, S_IRUGO);

struct example_module {
    u32 version;
};
static struct example_module module_struct;

static int __init m_init(void)
{
    module_struct.version = uint_param;
    pr_info("Hello World! uint_param=%u\n", module_struct.version);
    pr_info("Address of module parameter uint_param: %px\n", &uint_param);
    return 0;
}

static void __exit m_exit(void)
{
    pr_info("Bye World!\n");
}

module_init(m_init);
module_exit(m_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Douglas Su");
MODULE_DESCRIPTION("An example module");
```

## Rewrite C module in Rust

Our C module has a structure named `example_module`, which describes our module.
Single field, `version`, in `struct example_module` has a type of `u32` and
records the current version of our module. To rewrite this part in Rust, we
declare a Rust structure with a `u32` `version` member which is identical to
C's counterpart:

```rust
struct ExampleModule {
    version: u32,
}
```

Next, we need to mimic the ability of `module_init()` function. This is
implemented via a member function `init()`:

```rust
impl kernel::Module for ExampleModule {
    fn init(_module: &'static ThisModule) -> Result<Self> {
        let module = ExampleModule {
            version: *module_parameters::uint_param.value(),
        };

        pr_info!("Hello World! uint_param={}\n", module.version);
        Ok(module)
    }
}
```

Module parameters are placed in a `module_parameters` module generated by
`module! { }`, and their values are read with `value()`.

`module_exit()` is replaced by `Drop` trait:

```rust
impl Drop for ExampleModule {
    fn drop(&mut self) {
        pr_info!("Bye World\n");
    }
}
```

## Author, Description, License and etc.

All of these macros listed below are now members of `module!{ }` macro:

```c
MODULE_LICENSE("GPL");
MODULE_AUTHOR("Douglas Su");
MODULE_DESCRIPTION("An example module");
```

In Rust:

```rust
module! {
    type: ExampleModule,
    name: "example_module",
    authors: ["Douglas Su"],
    description: "An example module",
    license: "GPL",
    params: {
        uint_param: u32 {
            default: 1,
            description: "uint parameter",
        },
    },
}
```

Different from C's `module_param()`, a parameter has no permissions field. Its
permission is always 0, so it is not shown in
`/sys/module/<module>/parameters/` and can only be set when loading the module.

## Make our `struct ExampleModule` be the module entry point

Just assign structure name to type field in `module!{ }` macro.

```rust
module! {
    type: ExampleModule,
    ...
}
```

## The whole rust code

```rust
#![allow(missing_docs)]

use kernel::prelude::*;

module! {
    type: ExampleModule,
    name: "example_module",
    authors: ["Douglas Su"],
    description: "An example module",
    license: "GPL",
    params: {
        uint_param: u32 {
            default: 1,
            description: "uint parameter",
        },
    },
}

struct ExampleModule {
    version: u32,
}

impl kernel::Module for ExampleModule {
    fn init(_module: &'static ThisModule) -> Result<Self> {
        let module = ExampleModule {
            version: *module_parameters::uint_param.value(),
        };

        pr_info!("Hello World! uint_param={}\n", module.version);
        Ok(module)
    }
}

impl Drop for ExampleModule {
    fn drop(&mut self) {
        pr_info!("Bye World\n");
    }
}
```

## Evolution

- A parameter used to be read under the parameter lock:

  ```rust
  let lock = THIS_MODULE.kernel_param_lock();
  let version = *uint_param.read(&lock);
  ```

  Now it is read with `module_parameters::uint_param.value()`, without a
  lock.
- A parameter used to have a `permissions` field, like the `perm` argument of
  C's `module_param()`. It is gone, so Rust module parameters are not shown in
  sysfs.
